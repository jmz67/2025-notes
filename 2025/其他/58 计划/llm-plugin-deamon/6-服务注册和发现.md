> 在单体应用向微服务架构演进的过程中，原本的单体应用会按照业务的需求被拆分成多个微服务，每个服务提供特定的功能，并可能依赖于其他的微服务。每个微服务实例都可以被动态部署，服务实例之间的调用可以通过轻量级的远程调用方式（HTTP，消息队列等）实现，他们之间通过预先定义好的接口进行访问。
> 由于微服务实例是动态部署，每个服务实例的地址和服务信息都可能动态变化，势必需要一个中心化的组件对各个服务实例的信息进行管理，该组件管理各个部署好的服务实例元数据，包括但不限于服务名，IP 地址，Port，服务描述，服务状态等。

## 6.1.2 服务实例注册服务信息
---

1. 在服务启动的阶段，提交自身服务实例元数据到服务注册和发现中心，完成服务注册。
2. 在服务运行的阶段，定期和服务注册和发现中心维持心跳，保证自身在线状态。如果可能，还会检测自身元数据的变化，发生变化时重新提交数据到服务注册和发现中心。
3. 在服务关闭时，向服务注册和发现中心发出下线请求，注销自身在注册表中的服务实例元数据。

## 6.1.3 CAP 原理
---
从本质上来讲，微服务应用属于分布式系统中的一种落地实践，而分布式系统的最大的难点在于处理各个节点之间的数据状态的一致性。即使是倡导无状态的 http restful api 请求，在处理多服务实例情况下的修改数据状态请求时，也是需要通过数据库或者分布式缓存等外部系统维护数据的一致性。CAP 原理是描述分布式系统下节点数据同步的基本原理。

Consistency Availability Partition tolerance CAP 定理由加州大学的 Eric Brewer 教授提出，他认为以上三个指标不可能同时满足，让我们来分析一下这三个指标。

1. Consistency 指的是数据一致性，表示系统的数据信息（包括备份的数据）在同一个时刻都是一致的。在分布式系统中，同一份数据可能存在于多个不同的实例中，在数据强一致的要求下，对其中一份数据的修改必须同步到它的所有备份中。在数据同步的任何时候，都需要保证所有对这份数据的请求讲返回同样的状态。
2. Availablity 
3. Partition tolerance 指的是分区容忍性。在分布式系统中，不同节点之间通过网络进行通信。基于网络的不可靠性，位于不同网络分区的服务节点可能会通信失败，如果系统可以容忍这种情况，说明它是满足分区容忍特性的。如果系统不能满足这个，那么将会限制分布式系统的扩展性，即服务节点的部署数量和地区将会受限，违背了分布式系统设计的初衷，所以一般来讲分布式系统都会满足分区容忍性。

## 6.2.1 基于 Raft 算法的开箱即用服务发现组件 Consul
---
Consul 由 HashiCoup 开源，是支持多个平台的分布式高可用系统。Consul 使用 Go 语言实现，主要用于实现分布式系统的服务发现和配置，满足 CP 特性。Consul 是分布式，高可用，可横向扩展的，提供以下主要特性：

服务发现

健康检查

Key/Value 

多数据中心：Consul 使用 Raft 算法来保证数据一致性，提供了开箱即用的多数据中心功能。

通过 Consul 实现服务注册和发现中心调用过程如下：

**注册**：Producer（服务生产者）启动时，通过 /register 接口把自己服务实例信息存到 Consul 里。比如一家外卖店（Producer）开业，就赶紧在 Consul 这个 “服务登记处” 登记自己的信息。

**健康检查**：Consul 会通过 /health 接口定期检查 Producer 服务状态。就像有人定期去外卖店看看，是不是正常营业。

**获取元数据**：Consumer（服务消费者）需要服务时，向 Consul 要 Producer 服务的元数据，也就是服务信息。好比顾客（Consumer）打开外卖平台（Consul）找外卖店（Producer）信息。

**调用服务**：Consumer 从 Consul 返回的 Producer 服务信息里，挑合适的 IP 和端口去调用服务，就像顾客选一家外卖店下单。

### Consul 架构角色

- **Consul Client**：没什么 “记忆” ，是无状态的。它收到 HTTP 或 DNS 接口请求，就转发给同数据中心的 Consul Server 处理。像个 “快递小哥”，只负责传递请求。

- **Consul Server**：是存储和复制数据的地方。多个 Server 一起组成高可用集群（官方建议 3 个及以上） ，它们用 Raft 协议选出一个 Leader 。同一数据中心的 Server 保证数据强一致性。跨数据中心请求时，本地 Server 会把请求转到远程处理，不同数据中心 Server 数据不同步。可以把 Server 看成 “仓库管理员”，负责数据存储和一些管理决策。

### Gossip 协议相关

- **Lan 池**：每个数据中心都有，管理本数据中心的 Server 和 Client 。能让 Client 找到 Server ，还分担故障检测，快速广播事件（比如选 Leader ）。类似小区的 “信息交流群”，方便区内成员交流协作。
- **Wan 池**：全局只有一个，管理所有数据中心的 Server ，让 Server 能处理跨数据中心请求。像是 “城市间联络站”，负责跨区域沟通。
