1. 题目01：请实现一个 Python 装饰器 retry，它可以在被装饰的函数抛出异常的时候自动重试 3 次，每次重试的间隔 2 秒。

考察点：异常处理，装饰器，时间控制

2. 题目02：假设你要设计一个基于 fastapi 或者是 flask 的大模型接口，要求：
- 接收用户输入的 prompt 并返回大模型的回答
- 支持流式的返回 Streaming Response 
- 限制每个用户一分钟最多调用十次

考察点：FastAPI，流式输出，速率限制 Rate Limiting 

3. 题目03：假设你要调用多个大模型 API，例如 OpenAI 和 Claude 的，你希望并行的调用这两个接口，并返回最快的结果。请使用 python 的 asyncio 和 httpx 实现这个逻辑。

考察点：异步编程，并发 HTTP 请求

4. 题目04：在 Dify 的二次开发中，我们需要存储用户的聊天记录。假设我们使用 PostreSQL，请设计数据库表结构，并使用 SQLAlchemy 定义相应的模型，要求：
- 记录用户 ID、对话 ID、用户输入、模型回答、时间戳；
- 允许用户根据 `对话 ID` 查询完整的聊天记录。

考察点：数据库设计、SQLAlchemy 使用。

5. 题目05：在 Dify 开发中，我们希望缓存大模型的 API 响应，以减少重复请求。请使用 **Redis** 实现一个缓存装饰器 `@cache_response`，使得相同的 API 请求在 10 分钟内不会重复调用，而是直接返回缓存结果。

考察点：Redis，缓存策略，装饰器设计

6. 题目06：为了提高大模型 API 的吞吐量，我们可以将请求放入 **消息队列** (RabbitMQ/Kafka)，由后台的 Worker 逐步处理。请实现一个基于 **Celery + Redis** 的任务队列：
- 接收用户 `prompt` 并加入任务队列；
- Worker 处理后将结果存入数据库，并通知用户查询结果。

考察点：Celery，任务队列，异步任务处理

7. 题目07：在 Dify 二次开发中，我们可能需要调用多个大模型 API（如 OpenAI GPT、Claude、Mistral）。请实现一个 Python 类 `LLMClient`，支持：
- 统一封装不同大模型 API 的调用方式；
- 可以动态切换不同的 API 提供商（比如 OpenAI、Anthropic）。

考察点：面向对象设计、抽象工厂模式、多大模型 API 适配。

8. 题目08：在 LLM API 的调用过程中，我们需要根据输入/输出 Token 数来计算成本。假设不同模型的 Token 价格如下：
- GPT-4: $0.03/1K 输入 Token，$0.06/1K 输出 Token
- Claude-2: $0.01/1K 输入 Token，$0.02/1K 输出 Token
请实现一个 Python 函数 `calculate_cost(model, input_tokens, output_tokens)`，计算调用成本。

考察点：计算逻辑、Python 函数设计、字典数据结构。

9. 题目09：Dify 允许开发自定义插件，请你基于 **Dify 插件 SDK** 设计一个插件，它可以：
- 解析用户输入中的时间（如“下周一”、“明天下午 3 点”）；
- 以标准 `YYYY-MM-DD HH:mm:ss` 格式返回解析后的时间。

考察点：Dify 插件开发、自然语言时间解析（可用 `dateparser` 库）。

10. 题目10：在开发大模型 API 时，如何确保代码的稳定性？

请为以下函数编写**完整的单元测试**（使用 `pytest`）：

```python
import requests

def fetch_model_response(prompt: str) -> str:
    url = "https://api.example.com/generate"
    response = requests.post(url, json={"prompt": prompt})
    return response.json().get("response", "")
```

考察点：单元测试、Mock、API 可靠性测试。
