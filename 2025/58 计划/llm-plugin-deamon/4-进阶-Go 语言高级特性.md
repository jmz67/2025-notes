在上一章中，我们对 Go 语言的基础语法和特性进行介绍，如数据类型，容器等。这一章我们将对 Go 语言中的一些高级特性进行介绍，包括包管理，反射和并发等。

代码的搞复用性是优秀代码必备的品质，而 Go 语言的包管理就为我们封装模块和复用代码提供了强有力的支撑。

Go 是一门静态强类型语言，在程序编译的过程中会将变量的反射信息如字段类型，类型信息等写入可执行文件中。在程序执行的过程中，Go 语言虚拟机会加载可执行文件中变量的反射信息，并提供接口用于在运行时获取和修改代码的能力。

Go 语言支持两种并发模型，一种是我们常见的共享内存并发模型；另一种是 Go 语言推荐使用的 CSP 顺序进程通信并发模型。Go 语言使用了一种特殊的 MPG 线程模型，使得可以原生态支持协程并发，大大提供了程序的执行效率。

## 4.3.2 CSP 并发模型
---
Go 语言中实现了两种并发模型：一种是我们熟悉的线程和锁并发模型，它主要依赖于共享内存实现。线程与锁模型类似于底层硬件运行过程的形式化，程序的正确运行很大程度依赖于开发人员的能力和技巧，程序在出错的时候不容易排错。另一种是 Go 语言中倡导使用的 CSP 通信顺序进程模型。

CSP 并发模型是 Tony Hoare 在 1977 年提出的一种并发编程方式。它的核心思想是：用“通信”来代替“共享内存”。在 CSP 模型中有两个重要的概念：

1. 并发体：可以理解为一个个独立执行的任务或线程，它们彼此不依赖，可以同时进行。
2. 通道：并发体之间靠通道来交换信息。

和传统的用共享内存+加锁的方式不同，CSP 模型里的并发体之间是完全独立的，它们没有共同的数据区。它们通过“通道”来收发数据。不管是发送数据还是接收数据，操作时都会“等着对方”，直到另一方完成操作，这种机制让数据交换变成一种自动的同步过程。

CSP 的重点不在“谁发的、谁收的”，而在于“消息通过什么方式传递”——也就是通道。发送方和接收方可能互相都不知道彼此是谁，但只要它们用的是同一个通道，就能顺利交换数据。通道可以像数据一样创建、传递、释放，还可以在多个并发体之间转来转去，灵活性非常高。

不过，通道的灵活也带来了问题。比如，一个并发体把数据发到一个没人会去读取的通道上，它就会一直卡在那儿动不了，程序就可能因此“死锁”，也就是彻底卡住不动了。

## 4.3.3 常见的线程模型
---
线程之间的调度本来就是个很复杂的问题，但在并发编程中，我们必须面对操作系统如何调度线程的情况。根据系统资源的不同，操作系统内部会把线程分成两类：用户线程和内核线程。用户线程本身不能直接使用计算机底层的资源，比如读写文件、访问网络等，如果要用这些资源，就得通过系统调用，让内核线程来帮忙。

线程是操作系统调度的最小单位，通常我们说的“线程”，主要有两种：

1. 用户线程是在用户程序空间中创建的，比如程序自己管理的协程、轻量线程等等。用户线程不需要操作系统的参与，创建和销毁都很快。但它有个问题，就是当多个用户线程在一个进程中运行时，它们之间争抢 CPU 是通过“进程”这个层面来参与的。也就是说，操作系统不知道这些用户线程的存在，它只看到整个进程，所以会把时间平均分配给这个进程，而不是每个线程。这就导致 CPU 的多核能力没有被好好利用。简单说，这种线程模型效率较低。
    
2. 内核线程由操作系统来管理和调度，它是真正由系统来控制的线程，能直接使用 CPU 等底层资源。当一个内核线程执行完或需要切换时，操作系统会把另一个线程调度到 CPU 上继续执行。这种方式能很好地利用 CPU 的多核能力，实现真正的并行执行。程序员如果想用这种线程，就需要通过系统提供的接口来调用。
    
用户线程不能直接控制 CPU 的使用，只有当用户线程所在的进程被系统调度后，才能运行这些线程。而内核线程可以被系统直接调度，真正实现按需分配 CPU 资源。因此，不同线程模型之间，CPU 使用效率也会有所不同。

### 用户级线程
---
想象一下，在用户级线程模型里，一个进程就像跟着一个小跟班，这个小跟班就是内核线程 。进程里面有好多线程，像线程 A、线程 B、线程 C ，它们的管理都交给用户代码去做。这就好比你自己管理自己的小团队，创建新成员、安排谁先干活、让大家同步做事这些操作，都很轻便高效。不过呢，这些复杂的管理工作得在用户代码里实现，一般得靠编程语言帮忙。

而且呀，这些线程没办法同时利用 CPU 的多核能力，只能轮流使用 CPU ，就像大家排队用电脑一样。要是哪个线程，比如线程 A 去请求 I/O 操作被卡住了，那整个进程都可能被拖累，因为进程对应的内核线程会因为线程 A 被卡住，而没办法使用 CPU ，整个进程就没法干活啦！

### 内核级线程模型
---
在内核级线程模型里，进程里的每个线程都有自己专属的内核线程小伙伴 。每创建一个新线程，就像给操作系统打个电话，让它帮忙在内核里创建一个新的内核线程。线程的管理和安排工作都交给操作系统这个 “大管家”。

![[Pasted image 20250511141959.png]]

不过呢，每次线程切换工作内容的时候，就像从家里跑到学校，得从用户态切换到内核态，这会消耗不少资源。而且能创建的线程数量，还得看操作系统内核能允许创建多少内核线程。但它也有好处，多个线程可以同时利用 CPU 多核一起计算，就像好几个人同时用好几台电脑干活。要是某个线程被卡住了，也不会影响其他线程继续工作。

### 两级线程模型
---
两级线程模型就像是把用户级线程模型和内核级线程模型的优点凑一块啦 。一个进程会对应好几个内核线程，进程里有个调度器，就像个小领导，决定进程里的线程怎么和内核线程配对。

![[Pasted image 20250511142022.png]]

进程会先向操作系统申请一些内核线程，然后把自己创建的线程和这些内核线程对应起来。线程的调用和管理由进程里的调度器负责，而内核线程的管理就交给操作系统。这样一来，既能减少创建和管理线程消耗的资源，又能让线程一起并行计算。不过呢，这对开发人员来说有点难，就像要解开复杂的谜题，得在程序代码里模拟线程调度的各种细节，比如切换线程时保存和恢复信息，管理栈空间大小等等。像 Go 语言的 MPG 模型，就是一种特别的两级线程模型，它把 CPU、内核线程、线程的关系，用 M、P、G 来描述，我们下一小节再详细说 MPG 线程模型。
